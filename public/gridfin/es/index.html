Concepto central

Qué es un Application Skeleton

Un Application Skeleton no es una app demo ni una carpeta de plantillas: es una base arquitectónica premontada para un producto. Gridfin fija el stack, la estructura, las reglas, la estrategia de testing y los quality gates antes de que Claude Code empiece a escribir features.

Arquitectura

El stack, las capas, los límites de imports y las reglas de cambio ya están elegidos, para que el agente no rearme el proyecto desde cero en cada feature.

Especificaciones

El trabajo empieza con un PRD y specs de features: primero queda claro qué construyes, después aparece el código.

Comprobaciones

Tests, lint, e2e y build corren como un único quality gate, para que el error sea visible antes del merge.

Proceso

Los skills y playbooks llevan el desarrollo por un ciclo repetible: idea → spec → código → tests → review → deploy.

Qué es un Application Skeleton — el desglose completo →

Qué obtienes

No una lista de promesas — un conjunto de componentes en tu propio repositorio de git.

Application Skeleton

Una base arquitectónica lista para tu aplicación — Next.js + TypeScript + Postgres. Ya viven dentro de ella:

✓ app/ ✓ tests/ ✓ playbooks/ ✓ hooks/ ✓ CLAUDE.md ✓ docs/rules/ ✓ quality gates ✓ updates

Además, actualizaciones para siempre. Es un repositorio de git que te pertenece. No es una suscripción, ni un servicio, ni un constructor de sitios alquilado.

Playbooks

Escenarios paso a paso para deploys, analítica, pricing, compliance y otras tareas de ingeniería donde no puedes fiarte de la memoria de la sesión.

Skills

Workflows de agente para onboarding, features, diseño, review, verificación, deploys, updates y registro de learnings.

Reglas de ingeniería

Reglas de arquitectura, frontend, testing, seguridad, documentación y proceso git por las que trabaja el agente.

Quality gates

Una sola pasada de lint, tests, e2e y build muestra el rojo antes del merge, no después del release.

Documentación

PRD, specs, ADRs, playbooks y reglas conservan el contexto entre sesiones para que el agente no reinicie el proyecto cada día.

¿Por qué no simplemente Claude Code?

Claude Code a secas escribe código, pero no te da un proceso de ingeniería estable. Sin Gridfin, cada sesión decide de nuevo cómo construir el proyecto; con Gridfin el agente trabaja con specs, reglas, hooks, tests y quality gates que no se pueden esquivar en silencio. El análisis completo: por qué el desarrollo con IA necesita reglas de ingeniería.

¿En qué se diferencia de un boilerplate — ShipFast y otros?

Los boilerplates venden código pre-armado que tú personalizas. Gridfin es un starter kit nativo para agentes: un esqueleto delgado más un proceso que especifica, construye y prueba tu producto específicamente. No recortas el dashboard de otro — haces crecer el tuyo.

¿Qué es un Application Skeleton?

Un Application Skeleton es la base arquitectónica sobre la que Claude Code construye tu producto concreto. No es solo una plantilla de proyecto: las decisiones de ingeniería sobre stack, estructura, tests y CI ya están tomadas, y el desarrollo posterior pasa por specs, skills y quality gates. El desglose completo: qué es un Application Skeleton.

¿En qué se diferencia de MakerKit y Supastarter?

MakerKit y Supastarter son boilerplates SaaS completos con instrucciones para agentes y soporte de pruebas. Gridfin resuelve otro problema: parte de tu idea y ejecuta un proceso guiado por specs cuyos hooks bloquean infracciones conocidas, cuyas pruebas deben demostrar que pueden fallar y cuyo gate ledger registra si el cambio está listo. Elígelos por funciones SaaS prefabricadas; elige Gridfin por un proceso de desarrollo aplicado a un producto enfocado.

¿Por qué el stack es fijo?

Porque todo el proceso — reglas, hooks, tests, gates, playbooks — está probado exactamente en este stack: Next.js + TypeScript, Tailwind + shadcn/ui, Postgres. La libertad de elegir stack son otras cuarenta decisiones que tendrías que tomar sin la experiencia.

¿Puedo usar mi propio stack?

No — y es deliberado. Gridfin no es un kit donde eliges tu propio stack: quita el stack fijo y desaparece todo lo que respalda — las reglas probadas, los tests y los gates. Si necesitas un stack diferente, la respuesta honesta es: Gridfin no es tu herramienta.

¿Qué necesito para ejecutar Gridfin?

Necesitas Claude Code, Git, una terminal y la toolchain compatible de Node.js/pnpm. Gridfin se ejecuta localmente como repositorio git y no requiere una cuenta alojada de Gridfin ni un runtime propietario.

¿Qué pasa si el proyecto deja de desarrollarse?

Nada terrible: el repositorio es tuyo, el código y el proceso funcionan localmente y no dependen de que Gridfin exista como producto. Dejarían de llegar actualizaciones — todo lo demás se mantiene.

¿Es adecuado para un principiante?

Si estás dispuesto a trabajar con una terminal, git y Claude Code siguiendo instrucciones paso a paso — sí: la caja lleva la arquitectura, la estrategia de testing y el control de calidad por ti. Si ves una terminal por primera vez — empieza con Lovable o Bolt.

¿Cómo evita Gridfin que la IA rompa el proyecto?

Gridfin hace visible el error antes del merge: cada cambio pasa lint, tests, e2e y build, y las reglas se imponen con hooks y quality gates. El agente puede escribir código rápido, pero no puede publicar un cambio sin las comprobaciones.
