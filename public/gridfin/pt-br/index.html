Sem experiência de engenharia, os erros são invisíveis — até ficarem caros

01

Você não sabe quais erros já está cometendo

Stack, arquitetura, testes, segurança — dezenas de decisões são tomadas em silêncio, sem uma segunda olhada.

O Gridfin toma as decisões de engenharia antes: a parte invariável já vem decidida e é reaproveitada em todo projeto.

02

Você conserta uma coisa, outra quebra

Construir foi rápido, depurar é infinito; cada nova feature esbarra nas anteriores.

Toda feature passa pelo mesmo ciclo: spec → código → testes → review. Os testes antigos impedem que uma nova feature quebre as anteriores em silêncio.

03

Cada nova feature custa mais que a anterior

Restrições que você não conhecia começam a aparecer; o agente reescreve metade da base de código por causa de uma mudança pequena.

O Application Skeleton trava a arquitetura desde o primeiro dia: a vigésima feature passa pelo mesmo processo que a primeira.

04

O Claude Code escreve código mais rápido do que você consegue revisar

O que exatamente ele gerou ontem — ninguém leu.

Hooks e quality gates fazem da revisão parte do processo: uma violação de regra é barrada antes de o código ser escrito, e o status vermelho fica visível antes do merge.

Conceito central

O que é um Application Skeleton

Um Application Skeleton não é um app de demonstração nem uma pasta de templates: é uma base arquitetural pré-montada para um produto. O Gridfin fixa o stack, a estrutura, as regras, a estratégia de testes e os quality gates antes de o Claude Code começar a escrever features.

Arquitetura

O stack, as camadas, os limites de imports e as regras de mudança já estão escolhidos, para o agente não remontar o projeto do zero a cada feature.

Especificações

O trabalho começa com um PRD e specs de features: primeiro fica claro o que você constrói, depois o código aparece.

Verificações

Testes, lint, e2e e build rodam como um único quality gate, para o erro ficar visível antes do merge.

Processo

Skills e playbooks conduzem o desenvolvimento por um ciclo repetível: ideia → spec → código → testes → review → deploy.

Por que não usar só o Claude Code?

O Claude Code sozinho escreve código, mas não dá um processo de engenharia estável. Sem o Gridfin, cada sessão decide de novo como construir o projeto; com o Gridfin, o agente trabalha com specs, regras, hooks, testes e quality gates que não podem ser contornados em silêncio. A análise completa: por que o desenvolvimento com IA precisa de regras de engenharia.

Qual a diferença para boilerplates como ShipFast e outros?

Boilerplates vendem código pré-montado que você personaliza. O Gridfin é um starter kit agent-native: um esqueleto enxuto mais um processo que especifica, constrói e testa o seu produto especificamente. Você não esculpe o dashboard de outra pessoa — você faz crescer o seu próprio.

O que é um Application Skeleton?

Um Application Skeleton é a base arquitetural sobre a qual o Claude Code constrói o seu produto. Não é só um template de projeto: as decisões de engenharia sobre stack, estrutura, testes e CI já foram tomadas, e o desenvolvimento segue por specs, skills e quality gates. O detalhamento completo: o que é um Application Skeleton.

Qual a diferença para MakerKit e Supastarter?

MakerKit e Supastarter são boilerplates SaaS completos com instruções para agentes e suporte a testes. O Gridfin resolve outro problema: parte da sua ideia e executa um processo guiado por specs, com Hooks que bloqueiam violações conhecidas, testes que precisam provar que falham e um gate ledger que registra se a mudança está pronta. Escolha-os por recursos SaaS prontos; escolha o Gridfin por um processo de desenvolvimento aplicado a um produto focado.

Por que a stack é fixa?

Porque todo o processo — regras, hooks, testes, gates, playbooks — foi provado exatamente nessa stack: Next.js + TypeScript, Tailwind + shadcn/ui, Postgres. A liberdade de escolher a stack é mais quarenta decisões que você teria que tomar sem ter a experiência.

Posso usar minha própria stack?

Não — e isso é proposital. O Gridfin não é um kit onde você escolhe a própria stack: tire a stack fixa e tudo que está por trás dela desaparece — as regras, testes e gates comprovados. Se você precisa de outra stack, a resposta honesta é: o Gridfin não é sua ferramenta.

O que preciso para executar o Gridfin?

Você precisa de Claude Code, Git, um terminal e a toolchain compatível de Node.js/pnpm. O Gridfin roda localmente como um repositório git e não exige conta hospedada do Gridfin nem runtime proprietário.

E se o projeto parar de ser desenvolvido?

Nada de grave: o repositório é seu, o código e o processo funcionam localmente e não dependem do Gridfin existir como produto. As atualizações parariam de chegar — o resto continua.

É indicado para iniciantes?

Se você está disposto a trabalhar com terminal, git e Claude Code seguindo instruções passo a passo — sim: a caixa carrega a arquitetura, a estratégia de testes e o controle de qualidade para você. Se você está vendo um terminal pela primeira vez — comece com Lovable ou Bolt.

Como o Gridfin impede que a IA quebre o projeto?

O Gridfin torna o erro visível antes do merge: cada mudança passa por lint, testes, e2e e build, e as regras são impostas por hooks e quality gates. O agente pode escrever código rápido, mas não pode lançar uma mudança sem as verificações.
