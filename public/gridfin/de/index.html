Ohne Engineering-Erfahrung sind Fehler unsichtbar — bis sie teuer werden

01

Du weißt nicht, welche Fehler du schon machst

Stack, Architektur, Tests, Security — Dutzende Entscheidungen fallen still, ohne zweiten Blick.

Gridfin trifft die Engineering-Entscheidungen im Voraus: Der invariante Teil steht fest und wird in jedem Projekt wiederverwendet.

02

Du reparierst eine Sache — eine andere geht kaputt

Bauen war schnell, Debugging endlos; jedes neue Feature berührt die vorherigen.

Jedes Feature durchläuft denselben Zyklus: Spec → Code → Tests → Review. Alte Tests verhindern, dass ein neues Feature die alten still bricht.

04

Ein Befehl — /gridfin — startet einen Guide-Agenten. Die Pipeline zeigt den Prozess und echte Artefakte bei jedem Schritt.

Kernkonzept

Was ist ein Application Skeleton

Ein Application Skeleton ist keine Demo-App und kein Ordner voller Templates — es ist ein vormontiertes architektonisches Fundament für ein Produkt. Gridfin legt Stack, Struktur, Regeln, Teststrategie und Quality Gates fest, bevor Claude Code die ersten Features schreibt.

Architektur

Stack, Schichten, Importgrenzen und Änderungsregeln sind schon gewählt, damit der Agent das Projekt nicht bei jedem Feature neu aufbaut.

Spezifikationen

Die Arbeit beginnt mit einem PRD und Feature-Specs: Erst ist klar, was gebaut wird, dann entsteht der Code.

Prüfungen

Tests, Lint, E2E und Build laufen als ein Quality Gate, damit ein Fehler vor dem Merge sichtbar wird.

Prozess

Skills und Playbooks führen die Entwicklung durch einen wiederholbaren Zyklus: Idee → Spec → Code → Tests → Review → Deploy.

Was du bekommst

Keine Liste von Versprechen — Komponenten in deinem eigenen git-Repository.

Application Skeleton

Ein fertiges architektonisches Fundament für deine Anwendung — Next.js + TypeScript + Postgres. Bereits enthalten:

✓ app/ ✓ tests/ ✓ playbooks/ ✓ hooks/ ✓ CLAUDE.md ✓ docs/rules/ ✓ quality gates ✓ updates

Plus Updates für immer. Es ist ein git-Repository, das dir gehört. Kein Abo, kein Service, kein gemieteter Baukasten.

Playbooks

Schritt-für-Schritt-Szenarien für Deploys, Analytics, Pricing, Compliance und andere Engineering-Aufgaben, bei denen man sich nicht auf das Gedächtnis der Session verlassen kann.

Skills

Agenten-Workflows für Onboarding, Features, Design, Review, Verifikation, Deploys, Updates und das Festhalten von Learnings.

Engineering-Regeln

Regeln für Architektur, Frontend, Testing, Security, Dokumentation und den Git-Prozess, nach denen der Agent arbeitet.

Quality Gates

Ein Lauf aus Lint, Tests, E2E und Build zeigt Rot vor dem Merge — nicht nach dem Release.

Dokumentation

PRD, Specs, ADRs, Playbooks und Regeln halten den Kontext zwischen Sessions, damit der Agent das Projekt nicht jeden Tag neu beginnt.

Warum nicht einfach Claude Code?

Claude Code allein schreibt Code, gibt dir aber keinen stabilen Engineering-Prozess. Ohne Gridfin entscheidet jede Session neu, wie das Projekt gebaut wird; mit Gridfin arbeitet der Agent nach Specs, Regeln, Hooks, Tests und Quality Gates, die sich nicht still umgehen lassen. Die ganze Analyse: warum KI-Entwicklung Engineering-Regeln braucht.

Was unterscheidet das von Boilerplates wie ShipFast?

Boilerplates verkaufen vorgefertigten Code, den du anpasst. Gridfin ist ein agent-natives Starter-Kit: ein schlankes Skeleton plus ein Prozess, der genau dein Produkt spezifiziert, baut und testet. Du meißelst kein fremdes Dashboard zurecht — du lässt dein eigenes wachsen.

Was ist ein Application Skeleton?

Ein Application Skeleton ist das architektonische Fundament, auf dem Claude Code dein konkretes Produkt baut. Es ist nicht nur ein Projekt-Template: Die Engineering-Entscheidungen zu Stack, Struktur, Tests und CI sind schon getroffen, und die weitere Entwicklung läuft über Specs, Skills und Quality Gates. Der ausführliche Beitrag: was ein Application Skeleton ist.

Was unterscheidet das von MakerKit und Supastarter?

MakerKit und Supastarter sind umfangreiche SaaS-Boilerplates mit Agentenanweisungen und Test-Unterstützung. Gridfin löst ein anderes Problem: Es beginnt mit deiner Produktidee und führt einen spec-getriebenen Prozess aus, dessen Hooks bekannte Verstöße blockieren, dessen Tests nachweislich fehlschlagen müssen und dessen Gate-Ledger die Lieferbereitschaft festhält. Wähle sie für fertige SaaS-Funktionen; wähle Gridfin für einen durchgesetzten Entwicklungsprozess rund um ein fokussiertes Produkt.

Warum ist der Stack fest?

Weil der ganze Prozess — Regeln, Hooks, Tests, Gates, Playbooks — genau auf diesem Stack bewährt ist: Next.js + TypeScript, Tailwind + shadcn/ui, Postgres. Freie Stack-Wahl bedeutet vierzig weitere Entscheidungen, die du ohne die nötige Erfahrung treffen müsstest.

Kann ich meinen eigenen Stack nutzen?

Nein — und das ist Absicht. Gridfin ist kein Baukasten mit freier Stack-Wahl: Ohne den festen Stack verschwindet alles, wofür er steht — die bewährten Regeln, Tests und Gates. Brauchst du einen anderen Stack, lautet die ehrliche Antwort: Gridfin ist nicht dein Tool.

Was brauche ich, um Gridfin auszuführen?

Du brauchst Claude Code, Git, ein Terminal und die unterstützte Node.js/pnpm-Toolchain. Gridfin läuft lokal als git-Repository und benötigt weder ein gehostetes Gridfin-Konto noch eine proprietäre Laufzeit.

Was, wenn das Projekt nicht mehr weiterentwickelt wird?

Nichts Schlimmes: Das Repository gehört dir, Code und Prozess laufen lokal und hängen nicht davon ab, dass es Gridfin als Produkt gibt. Updates würden ausbleiben — alles andere bleibt.

Ist das für Einsteiger geeignet?

Wenn du bereit bist, mit Terminal, git und Claude Code nach Schritt-für-Schritt-Anleitung zu arbeiten — ja: Die Box übernimmt Architektur, Teststrategie und Qualitätskontrolle für dich. Siehst du zum ersten Mal ein Terminal — starte mit Lovable oder Bolt.

Wie verhindert Gridfin, dass KI das Projekt kaputt macht?

Gridfin macht einen Fehler vor dem Merge sichtbar: Jede Änderung durchläuft Lint, Tests, E2E und Build, und die Regeln werden durch Hooks und Quality Gates erzwungen. Der Agent darf schnell Code schreiben, aber keine Änderung ohne Prüfungen ausliefern.
