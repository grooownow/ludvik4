早期アクセス — ベータテスターは無料

高品質なサイトとアプリのためのClaude Code starter。

Gridfinは、空のリポジトリをApplication Skeleton——Claude Codeで開発するための出来上がったアーキテクチャ基盤——に変えるagent-nativeなstarter kitです。スペック、エンジニアリングルール、hooks、テスト、quality gatesが最初から組み込まれています——混沌としたvibe codingの代わりに。

アイデアとClaude Codeはあるけれど、長年のエンジニアリング経験がない——そんなあなたを、Gridfinはエンジニアリングチームが何年もかけて築くプロセスに沿ってガイドします。

01

自分がすでに犯しているミスに気づけない

スタック、アーキテクチャ、テスト、セキュリティ——数十の判断が、見直されないまま静かに下される。

Gridfinはエンジニアリングの判断をあらかじめ済ませています。不変の部分は決定済みで、すべてのプロジェクトで再利用されます。

02

一つ直すと、別の場所が壊れる

構築は速かったのに、デバッグは終わらない。新機能はどれも既存の機能に触れてしまう。

すべての機能が同じサイクルを通ります——仕様 → コード → テスト → レビュー。既存のテストが、新機能による既存機能の静かな破壊を防ぎます。

03

新機能を追加するたびにコストが増えていく

知らなかった制約が次々に表面化し、小さな変更のためにエージェントがコードの半分を書き直す。

Application Skeletonが初日からアーキテクチャを固定します。20個目の機能も、1個目と同じプロセスで実装されます。

04

Claude Codeはレビューが追いつかない速さでコードを書く

昨日生成された内容を、正確に読んだ人は誰もいない。

フックと品質ゲートがレビューをプロセスの一部にします。ルール違反はコードが書かれる前に止まり、赤信号はマージ前に見えます。

Gridfinはプロセスを直す·まず仕様·次にコード·そしてテスト·一つのルールセット

中心概念

Application Skeletonとは

Application Skeletonはデモアプリでもテンプレート集でもなく、プロダクトのために事前に組み上げられたアーキテクチャ基盤です。GridfinはClaude Codeがフィーチャーを書き始める前に、スタック、構造、ルール、テスト戦略、quality gatesを固定します。

アーキテクチャ

スタック、レイヤー、importの境界、変更ルールはすでに選ばれていて、エージェントがフィーチャーのたびにプロジェクトを作り直すことはありません。

スペック

作業はPRDとフィーチャーのスペックから始まります。まず何を作るかが明確になり、その後にコードが生まれます。

チェック

テスト、lint、e2e、ビルドがひとつのquality gateとして実行され、ミスはマージ前に可視化されます。

プロセス

skillsとプレイブックが、アイデア → スペック → コード → テスト → レビュー → デプロイという繰り返し可能なサイクルで開発を導きます。

Application Skeletonとは — 詳しい解説 →

得られるもの

約束のリストではなく、あなた自身のgitリポジトリの中にある一式のコンポーネントです。

Application Skeleton

あなたのアプリケーションのための構築済みアーキテクチャ基盤——Next.js + TypeScript + Postgres。すでに内蔵されているもの:

✓ app/ ✓ tests/ ✓ playbooks/ ✓ hooks/ ✓ CLAUDE.md ✓ docs/rules/ ✓ quality gates ✓ updates

さらに、永久のアップデート付き。あなた自身が所有するgitリポジトリです。サブスクリプションでも、サービスでも、レンタルのサイトビルダーでもありません。

プレイブック

デプロイ、アナリティクス、プライシング、コンプライアンスなど、セッションの記憶に頼れないエンジニアリング作業のためのステップバイステップのシナリオ。

スキル

オンボーディング、フィーチャー、デザイン、レビュー、検証、デプロイ、アップデート、learningsの記録のためのエージェントワークフロー。

エンジニアリングルール

アーキテクチャ、フロントエンド、テスト、セキュリティ、ドキュメント、gitプロセスに関する、エージェントが従うルール。

品質ゲート

lint、テスト、e2e、ビルドを一度に実行し、リリース後ではなくマージ前に赤を表示します。

ドキュメント

PRD、スペック、ADR、プレイブック、ルールがセッション間のコンテキストを保ち、エージェントが毎日プロジェクトをやり直さないようにします。

週末より多くのアイデアがある？

一つのキットで——プロジェクト数は無制限:SaaS、ランディングページ、個人プロジェクト。どのローンチもエージェントとの1時間で済み、1週間のセットアップは不要です。

よくある質問

製品スタック初心者向け動作要件購入
なぜClaude Codeだけではだめなのか？

Claude Code単体はコードを書きますが、安定したエンジニアリングプロセスは与えてくれません。Gridfinなしでは、セッションごとにプロジェクトの作り方を決め直します。Gridfinがあれば、エージェントはスペック、ルール、hooks、テスト、静かに回避できないquality gatesに従って働きます。詳しくは: AI開発にエンジニアリングルールが必要な理由。

ShipFastなどのボイラープレートとの違いは？

ボイラープレートは組み立て済みのコードを売り、あなたがカスタマイズします。Gridfinはエージェントネイティブなスターターキットです:薄い骨格に、あなたの製品を具体的に仕様化・構築・テストするプロセスが加わります。他人のダッシュボードを削って使うのではなく、自分自身のものを育てます。

Application Skeletonとは何か？

Application Skeletonは、Claude Codeがあなたのプロダクトを組み上げていくためのアーキテクチャ基盤です。単なるプロジェクトテンプレートではありません。スタック、構造、テスト、CIに関するエンジニアリング上の意思決定がすでに済んでいて、その後の開発はスペック、skills、quality gatesを通して進みます。詳しくは: Application Skeletonとは。

MakerKitやSupastarterとの違いは？

MakerKitとSupastarterは、エージェント向け指示とテスト支援を備えた高機能なSaaSボイラープレートです。Gridfinは別の課題を解きます。製品アイデアからspec駆動プロセスを実行し、Hooksが既知の違反を止め、テストが実際に失敗できることを証明し、gate ledgerが変更の出荷可否を記録します。既製SaaS機能なら前者、焦点を絞った製品の強制開発プロセスならGridfinです。

なぜスタックが固定なのか？

ルール、フック、テスト、ゲート、プレイブックというプロセス全体が、まさにこのスタック——Next.js + TypeScript、Tailwind + shadcn/ui、Postgres——で実証されているからです。スタックを自由に選べるということは、経験なしに下さなければならない判断がさらに40個増えるということです。

自分のスタックを使えるか？

いいえ——それは意図的な選択です。Gridfinはスタックを自由に選べるキットではありません:固定スタックを取り除くと、それが支えているもの——実証済みのルール、テスト、ゲート——もすべて消えてしまいます。別のスタックが必要なら、正直に言うと、Gridfinはあなたのツールではありません。

Gridfinの実行に必要なものは？

Claude Code、Git、ターミナル、対応するNode.js/pnpmツールチェーンが必要です。Gridfinはローカルのgitリポジトリとして動作し、ホスト型Gridfinアカウントや独自runtimeは不要です。

プロジェクトの開発が止まったらどうなるか？

深刻な問題にはなりません:リポジトリはあなたのものであり、コードとプロセスはローカルで動作し、製品としてのGridfinの存続に依存しません。アップデートは止まりますが、それ以外はすべて残ります。

初心者にも向いているか？

ターミナル、git、Claude Codeをステップバイステップの手順で扱う準備があるなら——はい:このボックスがアーキテクチャ、テスト戦略、品質管理をあなたの代わりに担います。ターミナルを見るのが初めてなら、LovableやBoltから始めてください。

GridfinはどうやってAIにプロジェクトを壊させないのですか?

Gridfinはミスをマージ前に可視化します。すべての変更はlint、テスト、e2e、ビルドを通り、ルールはhooksとquality gatesで強制されます。エージェントは速くコードを書けますが、チェックなしで変更を出荷することはできません。
