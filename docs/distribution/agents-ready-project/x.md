**Пост 1 (хук, его же закрепить):**
Частая история: «поставили Claude Code, а он ломает конвенции и кладёт файлы не
туда». В большинстве случаев дело не в агенте — проект к нему не подготовлен.
Собрала, из чего состоит подготовка. Тред 🧵

**Пост 2:**
1/ AGENTS.md — карта проекта для агента.
README объясняет проект людям, AGENTS.md — агентам: стек, команды, жёсткие
инварианты, ссылки на детальные правила. Главное — коротко: файл на 400 строк
агент «читает», но не соблюдает.

**Пост 3:**
2/ Правила по темам, а не монолит.
Отдельные файлы — тесты, архитектура, безопасность — со ссылкой на живой
код-образец. Агенты отлично копируют паттерны и плохо следуют абстрактной прозе.

**Пост 4:**
3/ Спеки до кода.
«Сделай оплату» → агент сделает какую-то оплату. Короткая спека (проблема →
сценарии → крайние случаи → что считается готовым) → сделает ту, что вы имели
в виду. Сильнее любого промпт-инжиниринга.

**Пост 5:**
4/ Механические ограничители + тесты.
Линтер с правилами архитектуры, pre-commit хуки, красный CI — дисциплина
держится на инструментах, не на словах. И: нет теста — нет фичи.
