# Форма заказа (RU) — спецификация

Статус: в разработке, локально (2026-10-28). Владелица согласовала поведение
в чате; точки входа — 2026-10-28.

## Зачем

Кнопки «Заказать» и «Обсудить проект» вели на /contact, где не было формы.
Telegram в России работает не у всех, поэтому одной ссылки «Написать в Telegram»
мало. Нужна заявка в один шаг, без регистрации. Ссылки на Telegram и почту
остаются как запасной путь.

## Точки входа

Одно окно (`<dialog>`) на весь сайт: `OrderProvider` в корневом layout,
кнопки — `OrderCta` (`src/features/site/order-cta.tsx`).

- **«Заказать»** на карточке пакета (`/uslugi`, `/uslugi/<вкладка>`) — окно с
  подставленными услугой, пакетом и ценой («Лендинги · Базовый · 20 000 ₽»).
- **«Обсудить проект»** и похожие: финал главной, финал `/uslugi`, «Расскажите
  идею» в последнем зале коллекции, «О студии», «Обсудить задачу» на
  страницах услуг `/uslugi/<slug>` — окно без услуги, заголовок «Обсудить
  проект». Выбора услуги нет (решение владелицы).
- **«Хочу такую анимацию»** в пузыре маскота — окно с услугой «Анимации и 3D»
  без пакета.
- **/contact** — та же форма прямо на странице, в карточке справа от контактов.
- Ссылка «Контакты» в шапке остаётся ссылкой на /contact.
- Без адреса функции и ключа капчи в сборке кнопки остаются ссылками на
  /contact, формы на /contact нет (как раньше).

## Поведение

- Поля:
  - «Как с вами связаться» (обязательно) — телефон, @ник, почта или ссылка;
  - кнопки выбора канала: Telegram, звонок, почта (необязательно);
  - «Пара слов о задаче» / «Расскажите о задаче» (необязательно, до 1000
    символов).
    Поля «Имя» нет: от человека нужен только контакт (владелица, 2026-10-28).
- Галочка согласия на обработку персональных данных. По умолчанию снята,
  без неё отправить нельзя. Рядом ссылки на согласие и политику.
- В заявку уходит страница, с которой её отправили (`page`), — она есть в
  письме.
- После отправки: «Получили вашу заявку! Скоро свяжемся…». Окно закрывается
  само через 4 секунды (или по «Хорошо»). На /contact сообщение остаётся, ниже
  «Отправить ещё одну заявку». При ошибке выводится текст ошибки, введённые
  данные остаются, ниже ссылки на Telegram и почту.
- Каждое открытие окна — пустая форма. Escape и крестик закрывают окно.
- Тема письма: «Заявка: Лендинги · Базовый» или «Заявка: Обсудить проект».

## Защита

1. Honeypot-поле и проверка времени: заявку, отправленную меньше чем через
   3 секунды после открытия окна, функция молча отбрасывает.
2. Невидимая Yandex SmartCaptcha. Токен проверяется на сервере
   (`POST https://smartcaptcha.cloud.yandex.ru/validate`), живёт 5 минут и
   действует один раз. Подпись капчи скрыта, поэтому в форме есть текст о том,
   что данные обрабатывает SmartCaptcha (этого требует Яндекс).
3. Проверка через zod на сервере (`src/features/order/order-schema.ts`). Ту же
   схему использует клиент, функция импортирует её при сборке.
4. Ограничение по IP в памяти экземпляра функции и ограничение
   масштабирования функции (`zone_instances_limit`, `zone_requests_limit`):
   поток запросов упирается в потолок и не превращается в счёт.
   Почему не API Gateway: расширение `x-yc-apigateway-rate-limit` устарело,
   замена (Smart Web Security) платная. Защита от DDoS на сетевом уровне — у
   платформы Yandex Cloud.
5. CORS разрешён только для `https://ludvik4.ru` (и localhost при разработке).

## Доставка

- Письмо со всеми полями приходит на российский ящик `ludvik4go@yandex.com`.
  Отправка через SMTP Яндекса (`smtp.yandex.ru:465`) с паролем приложения.
- Сигнал в Telegram через бота @ludvik4bot: «Новая заявка: <услуга> · <пакет>.
  Подробности на почте». Без персональных данных: в Telegram они не уходят,
  потому что это была бы трансграничная передача.
- Если Telegram недоступен из Yandex Cloud, письмо всё равно уходит. Telegram
  из Yandex Cloud недоступен (2026-10-28) — замена сигнала решается. MAX не
  используем никогда.
- Позже: бот, который сразу отвечает клиенту.

## Секреты (Lockbox, вводит владелица сама)

`SMTP_PASSWORD` (пароль приложения Яндекс Почты), `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_CHAT_ID`, `SMARTCAPTCHA_SERVER_KEY`.

## Сайт (переменные сборки)

`NEXT_PUBLIC_ORDER_ENDPOINT` — адрес функции.
`NEXT_PUBLIC_SMARTCAPTCHA_SITE_KEY` — ключ клиентской части.
Если их нет, «Заказать» ведёт на /contact, как раньше, и прод не ломается.

## Тесты

Схема (валидные и невалидные контакты, обязательное согласие, ссылки в имени),
обработчик функции (honeypot, слишком быстрая отправка, капча не пройдена,
успех: письмо отправлено и сигнал без персональных данных), форма (данные
пакета подставлены, без согласия отправить нельзя, успех и ошибка).
