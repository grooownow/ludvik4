# International SEO, SRO, and Technical Audit

## Verdict

The live EN root was technically indexable, but the international source was
not commercially complete or semantically isolated. Only Home and Privacy were
in the sitemap; no service, evidence, or About pages existed. The `.dev` host
also served a Russian Gridfin mini-site and published `humans.txt` and
`security.txt` canonicals for `ludvik4.ru`. The root passed the lightweight
indexing gate but lacked the page network and source consistency needed for
category retrieval, buyer evaluation, or reliable AI understanding.

The production implementation now contains eight EN indexable URLs, removes RU-only
static files from the EN build, makes service files market-scoped, adds service
and evidence schema, corrects heading hierarchy, and disables
non-essential EN analytics to match the privacy notice. Production retesting on
2026-08-11 confirmed all eight URLs and the market-scoped service files.

The implementation also removes the historical `/blog/*` redirect to the RU
domain. Sending an international buyer to a Russian-language source was an
unnecessary market association and contradicted the English-source strategy.

## Live evidence captured before changes

Checked 2026-08-10:

- `service_files_audit.py https://ludvik4.dev`: pass at the transport/file
  level; it did not validate cross-market semantics.
- `indexing_preflight.py https://ludvik4.dev/`: 200, index/follow,
  self-canonical, in sitemap.
- Live sitemap: exactly `/` and `/privacy`.
- `https://ludvik4.dev/gridfin`: 200 after redirect normalization, Russian H1
  and title, `lang="ru"`, links/canonicals involving `ludvik4.ru`.
- `https://ludvik4.dev/humans.txt`: declared Russian language and `.ru` site,
  sitemap, and LLM overview.
- `https://ludvik4.dev/.well-known/security.txt`: canonical pointed to `.ru`.
- `/signin`: 200 with noindex metadata; `/dashboard`: 307 to sign-in. They were

- Web search for `site:ludvik4.dev`, the exact domain, and brand/category
  combinations returned no reliable indexed Ludvik4 result. This is a manual
  observation, not a substitute for Search Console.

The main issue was not keyword density or missing metadata. It was retrieval
architecture: an abstract H1, three unlinked service cards, no proof/source
nodes, only three internal links, mixed language artefacts on the host, and no
page capable of answering a service-specific buying question independently.

## Implemented fixes

### Critical

- Moved Gridfin static files from shared `public/` into an RU-only resource
  tree copied only after the RU static export.
- Replaced shared RU `humans.txt` and `security.txt` files with market-scoped
  route output and host-correct canonicals.
- Disabled PostHog loading in the EN build even when a live key remains in the
  deployment environment, aligning runtime behaviour with the EN privacy
  notice.

### Important

- Added three English service pages, Work, qa-pilot case, and About.
- Expanded sitemap and `llms.txt` from two URLs to the complete EN network.
- Added self-canonical metadata and Service, CreativeWork, Breadcrumb,
  Organization, WebSite, ProfessionalService, and FAQ structured data where
  the visible content supports it.
- Rewrote the Home H1 and first paragraph around explicit services, audience,
  geography, and delivery outcome.
- Added entity-based header, body, and footer internal links.

### Accessibility and performance

- Added the missing services H2 and corrected process heading levels.
- Preserved the approved `#ff4fb6` rose token and existing module-label colour;
  accessibility work must not alter the signed-off visual identity.
- Stopped priority-loading the desktop-only hero image on mobile.
- Eliminated EN PostHog replay/survey requests and related main-thread work.

## Local candidate retest

The production-shaped local EN build was checked before handoff:

- All eight sitemap URLs returned 200 with English titles and H1s.
- `/gridfin`, a nested Gridfin URL, and `/blog` returned 404.
- `/signin` remained reachable to crawlers and declared `noindex,nofollow`.
- Three mobile Lighthouse runs before the palette correction scored 94
  Performance, 100 Accessibility, 100 Best Practices, and 100 SEO. Those runs
  are retained as historical evidence, not as the final brand-preserving
  accessibility result. LCP was 3.1 seconds, CLS was 0, and TBT was 0–10 ms.
- The RU static export completed separately and retained the RU Gridfin files
  and correct RU service-file output.
- The repository gates passed: lint, 340 unit/component/integration tests, and
  28 desktop/mobile end-to-end tests.

The remaining 3.1-second lab LCP is above the 2.5-second good threshold and is
the primary performance follow-up after production deployment.

## Residual risks and external steps

1. Deploy the EN build before treating any local result as production evidence.
2. Re-run service-file audit, indexing preflight for all eight URLs, Lighthouse
   three times, structured-data validation, and a broken-link crawl.
3. Inspect the `sc-domain:ludvik4.dev` property in Google Search Console, submit
   the expanded sitemap, and inspect/request the Home plus three service URLs.
   No DNS, ownership, or property changes are authorised by this audit.
4. Remove the unused auth/database stack in a separate engineering change; the
   noindex correction is SEO-safe but does not remove unnecessary code weight.
5. Add another international case only when public evidence does not disclose
   the excluded market context.
6. The brand name collides with unrelated historical/person identifiers in
   search. Consistent category qualifiers and external profiles are required;
   a name change is not recommended without business evidence.

## Wave 2 follow-up — 2026-08-11

The first supporting semantic layer is implemented as four routes: a `/guides`
hub and one original decision worksheet for each service cluster. The candidate
contains twelve sitemap URLs, bidirectional service/guide links, expanded
`llms.txt`, and Article/Breadcrumb schema. It reuses the approved components and
tokens; no palette or shared chrome class changed.

Public search still provides no reliable evidence that the existing pages are
indexed. Search Console is authenticated as `krobox@gmail.com`, but that account
does not own the existing domain property. Ownership verification is therefore
the only external blocker to sitemap submission and URL Inspection.
